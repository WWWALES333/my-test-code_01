# Evidence To Insight

当任务目标是“把一批证据归纳成业务结论卡”时，使用本 skill。

## 何时触发
- 用户要求总结某类 AI 证据
- 用户要求提炼云诊室 / 云管家 / 销售行为 / 产品机会结论
- 用户要求从原文片段中形成可读结论，并保留追溯链路

## 不要用于
- 直接从原始文档做抽取
- 直接替代标签器
- 输出不可追溯的总结
- 处理正式复核状态写回

## 工作流
1. 先读取 `references/input_contract.md`，确认输入对象和允许主题。
2. 检查证据簇质量，先排除模板文本、资料整理和弱信号片段。
3. 归纳时固定回答：
   - 这组证据在说什么
   - 对业务意味着什么
   - 由哪些销售或区域体现最明显
4. 输出前检查：
   - 每张结论卡至少带 2 条代表证据或明确说明证据不足
   - 结论语言不能脱离原文证据
   - 若证据冲突，标记 `needs_review`

## 失败边界
- 如果证据簇过于分散或互相冲突，不得强行总结。
- 如果证据主要是弱信号或泛趋势表述，应明确降级为背景观察。
- 如果无法回到原文路径，不得输出正式结论卡。

## 输出要求
- 只输出 `references/output_contract.md` 定义的字段。
- 结论必须能被业务方直接阅读理解。
- 不要把标签名直接当结论标题。
