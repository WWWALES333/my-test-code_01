# v1.5 变更记录

**版本**：v1.5  
**状态**：封板版
**版本名称**：AI 一线情报工作台 MVP

## 1. 本版目标
把 `v1.4` 的离线试运行产物升级为可持续使用的 AI 一线情报工作台，重点补齐趋势判断、销售个人分析、结论提炼和复核回写闭环。

## 2. 本版新增
- 统一 Web 工作台：总览、趋势、销售、结论、复核、证据六个模块。
- `v1.5` 规范化中间层：销售归一、报告事实、证据事实、月度聚合、结论卡、复核任务、复核结果、工作台快照。
- 文件回写型复核闭环。
- 规则初筛 + LLM 边界判定的混合识别链路，保留 `mock/real` 双模式。
- 花名册接入与销售个人画像，当前人员主数据不入库。
- 首批 2 个项目内 skill 文档试点：
  - `trend-insight-analysis`
  - `evidence-to-insight`
- 系统解释材料：
  - `business_implementation_architecture.md`
  - `model_rule_prompt_map.md`
  - `product_participation_map.md`
  - `system_flow.mmd`
- 下载主链路同步补齐：月报 1-5 日窗口、单次运行 `--report-type`、运行日志原子写入、缺失月报审计告警。

## 3. 本版不做
- 不做正式数据库
- 不做多专题统一平台
- 不做经营结果数据关联
- 不做复杂权限系统
- 不把项目内 skill 作为运行时自动模块强绑定
- 不提交邮箱配置、API Key、人员花名册 Excel 等本地私有数据

## 4. 已知风险
- 销售个人归一短期内仍依赖映射表和规则归一。
- 文件回写方案不适合多人并发，首版只适用于轻量复核。
- 结论卡自动归纳存在噪声风险，需要证据追溯和人工复核兜底。
- `real` 模式需要本机环境变量 `OPENAI_API_KEY`、`OPENAI_MODEL`、`OPENAI_BASE_URL`，仓库不保存密钥。
- 当前主邮箱未检索到目标销售 `2026年04月月报`，审计已能明确告警为 0 份，但不能凭空补齐不存在的邮件附件。
- 全量历史重建耗时较长，封板检查优先使用既有归一化产物和单元测试验证。

## 5. 后续方向
- 优先讨论 `v1.6` 是否引入正式数据库、多人协作和更完整的复核学习闭环。
- 继续优化趋势解释和结论卡质量，使其从展示型看板升级为更强的一线情报系统。
- 若首批 skill 试点有效，再考虑提炼到本机全局 `~/.codex/skills`。
